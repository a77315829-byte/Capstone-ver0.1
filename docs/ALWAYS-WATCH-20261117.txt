AI 라면 상시 감시·최근 결과 우선 표시 / 2026-11-17 최종 추가 검증

DB 연결 문제 해결
- 이전 AI 판단 서비스의 별도 MONGO_URI가 유효하지 않은 주소를 덮어쓰고 있었음.
- 다른 ANTITUDE 프로젝트의 .env 후보를 키 내용 출력 없이 검색·연결 검증.
- 정상 server/.env의 MongoDB 연결을 재사용하고, 기존 판단 DB 이름 entitude 유지.
- 다른 판단 DB도 있었으나 원래 설정된 entitude의 기존 기록 57개를 그대로 보존.
- 원본 PC의 다른 프로젝트 .env는 수정하지 않음. 작업본과 학교 ZIP의 잘못된
  판단 URI 재정의만 제거. 기존 사용자 계좌·자금·매매/환전 데이터 변경 없음.
- 이제 판단 서비스 health는 ok / database connected.

새 동작
- npm start(또는 start-exhibition.bat)만 실행하면 5종목을 자동 감시:
  삼성전자 005930, SK하이닉스 000660, 현대차 005380, NAVER 035420, 카카오 035720.
- 시작 시 최근 거래일 자료로 각 종목의 초기 결과를 준비. 이미 최근 결과가 있으면 재사용.
- 이후 평일 KST 09:00~15:30 및 KRX_CLOSED_DATES 설정에 따라 장중 60초마다 시세 확인.
  웹과 같은 휴장일 설정을 사용하며 거래소 특수 개장일은 운영 일정 설정에 별도 반영 필요.
- 의미 있는 가격 누적 변동/지표 변화가 있을 때 판단을 갱신하고 DB에 저장.
  60초마다 무조건 AI 호출/기록 추가하는 방식이 아님. 같은 입력은 반복 저장하지 않음.
- 같은 종목의 AI 재생성 간격은 최소 5분. 서버 재시작 후에도 DB 시각으로 제한 유지.
- AI 생성은 한 번에 한 종목씩, 중복 작업은 병합하고 실패하면 간격을 두고 재시도.
- 고정 5종목은 패널을 닫거나 브라우저를 종료해도 감시 유지.
- 그 밖의 종목은 기존처럼 패널을 열 때 임시 감시, 닫거나 유지 요청 만료 시 해제.
- 서버를 끄면 새 수집은 멈추지만 DB에 저장된 이력은 유지.

빠른 화면 표시
- 감시 등록 API는 AI 생성을 기다리지 않고 즉시 응답.
- AI 라면은 DB의 최근 결과와 브라우저 메모리 캐시를 먼저 표시하고 뒤에서 갱신.
- 본인의 판단을 먼저 고르는 교육 흐름은 유지. 선택 직후 저장된 판단/근거를 공개하고
  비교 AI 해설은 비동기로 채움. 비교 해설이 실패해도 기존 판단은 유지.
- 느린 이전 종목/이전 시각의 응답은 새 종목/새 판단을 덮어쓰지 못하도록 처리.
- 최신 분석/비교 해설 갱신 중 상태와 실제 분석 시각 표시.
- 최신 조회용 MongoDB symbol+time 인덱스 추가. 기존 문서 삭제/변경 없이 추가함.
- AI 라면 외의 시장시뮬·급여 AI 등 새로운 입력을 분석하는 기능의 생성 시간은 이번 변경 대상 아님.

실제 검증
- AI 판단 서비스 자동 검사 47개 통과(기존 30개 + 상시 감시/갱신 17개).
- 브라우저를 열거나 /watch를 호출하지 않은 상태에서 서버만 시작.
  5종목 모두 실제 Ollama 판단 해설 생성, source ai-judgment / fallback false 확인.
- 기존 이력 57개 보존 + 실제 신규 5개 = 총 62개 저장 확인.
- 5종목 최근 결과 조회 시간 각각 47~63ms(이 PC/DB 연결에서 측정).
  이는 저장 결과 조회 시간이며 새로운 AI 해설 생성 시간이 아님.
- DELETE watch 후에도 5종목 목록 유지, 판단 DB connected 확인.
- 브라우저에서 비교 해설 갱신 중에도 기존 판단/근거가 먼저 보이는 것 확인.
- 새 판단 이력과 기존 11월 기록을 같은 히스토리에서 확인.
- AI 생성 지연을 제어한 HTTP 검사: 이전 결과 즉시 조회 → 생성 완료 후 새 결과 조회 통과.
- 고정 감시 TTL/닫기 유지, 임시 감시 만료, 장 시간/휴장일 경계, 중복·동시 실행 제한,
  실패 후 재시도, 최근 결과 재사용, 동일 입력 반복 저장 방지, 종료 시 작업 취소 통과.
- 웹 프로덕션 빌드 성공. 기존 별도 페이지들의 전체 타입 검사 오류는 남아 있음.
  이번 수정한 components/AiRamenPanel.tsx와 judgment.service.ts에는 새 오류 없음.

UI 변경 범위

학교 PC
- 최신 ZIP 안의 .env 그대로 사용. 판단 DB를 나중에 별도로 전달할 필요 없음.
- 기존 설치/실행 순서 유지: 압축 해제 → setup-exhibition.bat → start-exhibition.bat.
- 이전 압축본 위에 덮어쓰기보다 새 폴더에 풀어 사용. 이 ZIP에는 실제 .env가 있으므로 비공개 보관.
- 8GB PC의 AI 초기 생성은 순차 진행되며 대기 중 CPU 부하는 낮음.
- 전시 중 전원 연결 및 Windows 절전 없음 설정 필요.
- 감시 종목 변경: services/ai-judgment-service/.env의 ALWAYS_WATCH_SYMBOLS JSON 배열 수정 후 재시작.
  []로 설정하면 상시 감시 해제. 웹에서 여는 종목의 임시 감시는 유지.
