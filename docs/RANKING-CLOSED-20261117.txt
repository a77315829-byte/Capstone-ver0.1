장 마감·개장 전 순위 조회 보완 — 2026-11-17

원인
- 미국 KIS 당일 순위가 장 시작 전 정상 응답 코드와 빈 목록을 반환했습니다.
- 기존 처리는 빈 목록도 정상 결과로 저장하여 화면의 순위를 없앴습니다.
- 시세 제공 서버가 지연되면 순위와 지수 조회를 모두 기다려 웹 요청이 시간 초과되는 문제도 확인했습니다.

수정
- 국장·미장, 거래량·거래대금·상승률·하락률의 마지막 정상 순위를 각각 MongoDB에 저장합니다.
- 빈 목록·전체 조회 실패·거래량이 모두 0인 초기화 결과로 기존 정상 기록을 덮어쓰지 않습니다.
- 서버 재시작 후에도 저장한 순위를 읽어 먼저 표시하며 뒤에서 갱신합니다. 원래 조회 일시를 유지합니다.
- 저장된 당일 순위가 없는 미장은 KIS의 최근 2거래일 순위로 대체 조회합니다.
  NDAY=1은 전일 단일 거래일 선택이 아닙니다. 평균거래량(a_tvol), 평균거래대금(a_tamt), 기간등락률(n_rate)을 사용합니다.
  UI에도 평균 거래량·평균 거래대금·기간 등락률과 '최근 2거래일' 기준을 표시합니다.
- 당일과 2거래일 데이터를 서로 섞어서 정렬하지 않습니다. 일부 거래소가 누락되면 안내하며 완전한 저장 기록을 덮어쓰지 않습니다.
- 당일 데이터가 다시 제공되면 자동으로 당일 순위로 돌아갑니다.
- 조회 요청을 공유하고 최근 기간 조회는 5분간 재사용합니다. 저장된 자료는 최대 7일 이내의 기록만 표시합니다.
- 지수 조회는 순위 표를 장시간 막지 않습니다. 저장 결과가 없는 최초 요청도 대기시간을 제한합니다.
- KIS 인증/일반 시세 HTTP 요청에 10초 기본 제한을 적용했습니다.
- 저장 문서는 시장·정렬·기간별 최대 16개이며 개인 계좌정보를 포함하지 않습니다.
- 기존 화면 배치와 색상은 유지하고 기준/조회 일시 안내와 표 열 이름만 수정했습니다.

검증
- 순위 관련 회귀 테스트 15개 통과: 빈 정상 응답, 시세 장애, 재시작 복원, 부분 누락, 0값 초기화,
  기간별 정확한 수치, 당일 복귀, 동시 요청 공유, 오래된 기록 배제, 느린 공급자에 대한 저장 결과 우선 표시.
- 실제 API: 국장·미장 4개 기준 모두 30개씩 수신. 수치 정렬과 상승/하락 방향 확인.
- 새 프로세스에서 공급 장애를 재현해 실제 DB의 8개 저장 순위와 원래 조회 일시 복원 확인.
- 실제 웹: 8개 순위 표 각 30행, 기준 버튼, 최근 2거래일 표시, 종목 링크 확인.
- 320/390/1440px 화면에 페이지 가로 넘침 없음, 브라우저 JavaScript 오류 없음.
- 실제 공급 지연 시 저장 결과 API 응답은 이번 검사에서 약 26~1,699ms였습니다. 네트워크에 따른 보장값은 아닙니다.
- 서버 TypeScript 컴파일, 프런트 배포 빌드, git diff --check 통과.

실행
- 기존 npm start와 학교 설치 절차를 그대로 사용합니다.
- 접속: /exchange?market=KR 또는 /exchange?market=US
- 순위 데이터와 저장된 기록을 모두 받을 수 없는 최초 오프라인 실행에서는 조회 지연/실패로 표시합니다. 가짜 순위는 생성하지 않습니다.
