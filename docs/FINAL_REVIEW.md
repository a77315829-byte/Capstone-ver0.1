## 적용

- Node가 React 빌드 파일과 API를 함께 제공하도록 구성. 현재 전시는 한 PC에서 npm start로 웹·API·AI를 함께 실행한다. 루트 실행기는 분리된 Python 가상환경, 포트 충돌 검사, 종료 처리를 제공하며 선택적 분리 실행도 지원한다. 별도 앱 프로젝트는 나중에 다루며 이번 작업 범위에 포함하지 않는다.
- MongoDB 실저장 유지. DB 연결 실패 시 시작 중단. 기존 사용자명으로 저장된 시나리오 진행 식별자를 유지.
- 로그인 입력 객체/NoSQL 연산자 차단, bcrypt 비동기 처리, JWT HS256·8시간 만료 검증, 아이디 고유 인덱스. 중복 아이디가 이미 있으면 명시적으로 실패하고 자료를 임의로 삭제하지 않음.
- 로그인/회원가입/분석 요청 제한, 본문 크기 제한, 민감 오류 응답 축소, 제한된 CORS, 보안 헤더.
- 시나리오·퀴즈 API에 로그인 및 세션 소유자 확인 추가. Python API에는 공통 서비스 키 적용. 브라우저에서 내부 서비스로 바로 접근할 필요 없음.
- 시장/판단 서버 미연결 및 Ollama 장애 시 명확한 규칙 대체. 없는 가격·신뢰도·저장 이력은 만들지 않음. 자금 플래너도 기존 계산식으로 대체하고 정상 DB에 저장.
- 공용 PC 토큰을 sessionStorage로 이동. 만료·로그아웃 처리 및 해당 사용자 퀴즈 캐시 정리. 기존 로그인은 다시 해야 함.
- 실제 서버 설정을 확인한 Turnstile 동작. 로컬 전시에서는 환경변수로 명시적으로 끌 수 있음.
- 개인정보 처리방침·이용약관 초안 추가. 운영 주체 ANTITUDE, 제공된 연락처 반영. 11월 18~19일을 전시 기간으로 기재했고 종료 후 보관·파기 시점은 미확정으로 명시.
- 실제 보이는 변경: 로그인/회원가입/페이지 하단의 작은 정책 링크, 키보드 포커스와 본문 건너뛰기, 대체 분석 출처 문구, 자금 플래너 결과 출처 알림. 기존 색상·전체 레이아웃 유지.
- HTML 한국어 언어값, 입력/버튼 접근성 이름, 현재 메뉴 표시, 미국 보유 종목 카드 키보드 선택 보완. 이미지 alt 속성의 정적 검사에서 누락 없음. 의미가 적절한지 및 차트의 완전한 스크린리더 대안까지 인증한 것은 아님.

## MongoDB 답변

회원, 모의투자, 시나리오/퀴즈 진행, 자금 플랜 등은 원래 실제 MongoDB를 사용하는 구조이고 이번에도 유지했다. 시장 반응 API는 원래 stateless여서 결과 학습 이력을 저장하지 않는다. 공시 RAG 자료 저장과 시장 분석 결과 저장은 서로 다른 기능이다. 판단 서버가 없을 때는 새 판단 이력을 저장한 것처럼 응답하지 않는다.

## 2026-11-17 최종 수정 및 재검증

아래 초기 점검의 AI/재무 미완료 항목을 다음과 같이 보완했다.

- 월급·자산 분석에 제한된 JSON 스키마와 출력량을 적용했다. 실제 Ollama 결과: 급여 LLM 약 26초, 자산 ollama 약 18~20초. 기존 결정론적 금액 검증과 RULES 대체 유지.
- 시장 분석은 다섯 투자자 관점을 한 번의 모델 요청으로 생성하고 관점별로 검증한다. 잘못된 관점만 대체하며, 정합성 검토·종합 해설과 고정 가중치를 유지한다. 최종 웹 API 75.0초, llm_status=ok, fallback_used=false, 공시 RAG 자료 2건을 확인했다. Python/Node/시장 화면 제한을 110/120/130초로 맞췄다. 이 CPU PC에서 여러 AI를 동시에 사용하면 지연·대체가 발생할 수 있다.
- Gemini 피드백에도 JSON 스키마/1024 토큰 제한을 적용했다. 실제 반도체 3턴 기준표와 합성 답안으로 gemini-3.5-flash-lite 생성 성공(약 4.6초)을 확인했다.
- 사용자 요청에 따라 다른 폴더의 환경설정 텍스트에서 기존 DART 키를 찾아 수정본 server/.env에 연결했다. 원본 설정은 변경하지 않았고 키는 코드/ZIP에 포함하지 않는다.
- 삼성전자·SK하이닉스 DART 연간/분기 실제 자료 조회 성공. KIS 재무 API 자체의 404/OPSQ0001은 남아 있으나 DART와 네이버 발표 실적을 통해 화면에 필요한 자료를 복구했다. 예상 실적 제외, 누락값을 0으로 만들지 않음, DART 정확한 금액 우선, 기간별 보완 출처 표시.
- 누적 실적을 단일 분기 금액으로 읽던 오류와 상세 시가총액 단위를 교정했다. 불완전한 재무 캐시를 6시간 유지하지 않고 60초 후 재조회한다.
- 국내 체결/투자자 동향 및 미국 호가/체결의 빠진 라우트를 연결했다. 국내 두 API의 실제 200 응답을 확인했다.
- 화면 수정은 기존 재무표의 데이터 연결, 연간/분기 전환, 실제 기간·단위·출처 표시뿐이다. 색상·배치는 변경하지 않았다. 브라우저에서 연간/분기 비교를 확인했다. 과거 시나리오는 실제 1턴 진입을 확인했으며 사용자 보고 오류는 당시 재현되지 않았다.
- 서버 TypeScript 및 프런트 Vite 빌드 통과. 시장 회귀 279개, 시나리오 24개, backend 15개, 프런트 12개 통과. launcher 3개/실시간 10개도 이번 작업 중 통과했다.

## 2026-11-17 개인 PC 실연동 추가 점검

- 사용자가 지정한 원본 server/.env 및 시나리오·판단 서비스 .env를 수정본으로 복사했다. 원본 폴더의 설정은 수정하지 않았으며 키 값은 배포물에서 제외한다. npm run setup 전체 설치와 빌드를 완료했다.
- 웹·시나리오 실제 Atlas 연결 성공. 기존 데이터가 있는 DB를 사용하며 seed/초기화하지 않았다. Windows 기본 DNS 조회는 성공하지만 Node의 SRV 조회가 시간 초과되어 같은 Atlas 서버 주소를 TLS 연결 문자열로 변환한 로컬 설정을 사용한다.
- 브라우저에서 테스트 계정 로그인, 과거 시나리오 시작, 차트/뉴스 표시, 1턴 답변 제출·채점·해설·2턴 이동을 확인했다. 서버 재시작 및 새로고침 뒤에도 2턴이 유지됐다. 시세·호가·네이버 뉴스도 실제 화면에 표시됐다. 장 마감 시간 점검이므로 장중 실시간 체결과 주문 체결까지 검증한 것은 아니다.
- Ollama 공식 휴대용 배포본의 SHA256을 검증하고 qwen2.5:1.5b, bge-m3를 설치했다. RAM 약 8GB/CPU 환경. 실제 한국어 생성 및 주식 도우미의 LLM 응답(약 23초)을 확인했다. 기존 7B/8B 모델은 이 PC에서 검증하지 않았다.
- 급여 플랜은 모델 응답 검증 실패 시 RULES로 전환되고 실제 MongoDB 저장/재조회까지 성공했다. 자산 조언은 60초 제한 후 fallback으로 전환됐다. 이 두 기능의 LLM 생성 성공을 확인한 것은 아니다.
- 시장 반응은 웹 요청에서 45초 제한 후 규칙 결과를 반환했다. 공시 RAG 자료(1,325개 chunk/10개 manifest)는 존재한다. bge-m3 설치 전 검색이 실패했고 설치 후 전체 AI 경로도 CPU 환경에서 지연되어 정상 완료를 확인하지 못했다. 웹이 대체 결과를 반환한 뒤에도 계속되던 분석 작업을 방지하기 위해 Python 전체 분석 제한 40초와 취소 회귀 테스트를 추가했다.
- 판단용 기존 MongoDB 호스트는 NXDOMAIN. 사용자 요청에 따라 올바른 설정을 나중에 전달받기로 했고 다른 DB로 옮기지 않았다. 기록 저장은 미검증, 규칙 기반 판단/비교 응답은 실제 API와 화면에서 확인했다. health가 DB 장애를 정상으로 표시하던 문제를 수정하고 테스트 2개를 추가했다.
- Gemini의 설정된 모델 목록과 짧은 실제 생성 요청은 성공했다. 실제 시나리오 턴 해설 호출에서는 ServerError가 발생해 규칙 해설로 대체됐다. SDK의 자동 재시도를 1회 시도로 제한하여 모델별 15초 제한이 반복 호출로 늘어나지 않도록 했다.
- KIS 재무정보의 대소문자 구분 요청 형식을 [한국투자증권 공식 예제](https://github.com/koreainvestment/open-trading-api/tree/main/examples_llm/domestic_stock/finance_financial_ratio)에 맞췄지만, 현재 연결에서는 재무비율/기타비율 404 및 손익/재무상태 API의 OPSQ0001 오류가 남아 있다. 현재가·호가·차트 성공과 재무정보 전체 성공을 구분해야 한다.
- Windows 가상환경의 자식 Python까지 통합 실행기가 종료하도록 보완했다. 서비스별 원래 DB URI 보존 회귀 테스트 1개를 추가했다. 실행 위치에 따라 생성되는 .kis-token-cache.json도 모든 폴더에서 Git 제외한다.
- 추가 화면 변경은 **규칙 대체 상태에서만** AI 판단/신뢰도 문구를 규칙 기반 판단/규칙 점수로 표시하는 것이다. 기존 색상·배치는 유지한다.
- 추가 검증: Node/프런트 회귀 34개, 시나리오 23개, 판단 DB health 2개, 시장 반응 277개(시간 초과 취소 포함), 합계 336개 재검사 통과. 서버 TypeScript·프런트 Vite 빌드 및 git diff --check 통과. 이전 검토의 판단 엔진/내부 인증 검사와는 별도 실행 기록이다.
- 수정 후 브라우저 시장 분석에서 규칙 결과를 확인했고, Python 504 응답과 Ollama 작업 취소 로그를 확인했다. 전체 시장 LLM 분석 성공을 뜻하지 않는다.
- npm start 한 번으로 웹/시나리오/시장/판단/Ollama가 실행되고 Ctrl+C 한 번으로 3010·8000·8002·8003·11434가 모두 해제되는 것을 확인했다.
- 테스트 계정 1개와 해당 급여/가상계좌/시나리오 기록 총 9개를 식별 후 정리했다. 기존 사용자·콘텐츠의 삭제나 seed는 수행하지 않았다.

## 의존성 (기존 감사 결과)

- [React Router 리다이렉트 권고](https://github.com/advisories/GHSA-wrjc-x8rr-h8h6)
- [React Router SSR 권고](https://github.com/advisories/GHSA-337j-9hxr-rhxg)

## 남은 운영 결정과 위험

1. 정책은 초안이다. 전시 날짜와 개인정보 보관 기간은 다르다. 전시 종료 후 DB·백업 파기일, 책임자, 호스팅 지역, 실제 외부 AI 제공자/전송 항목 및 필요한 동의 절차를 운영자가 확정해야 한다. 별도의 확정되지 않은 동의 체크박스는 추가하지 않았다. [개인정보보호위원회 작성지침](https://www.privacy.go.kr/front/bbs/bbsView.do?bbsNo=BBSMSTR_000000000049&bbscttNo=20885)
2. 학교 LAN과 외부 공개 서비스는 구성이 다르다. 현재 기본은 loopback이다. 외부 공개 시 HTTPS, 프록시 신뢰 설정, CAPTCHA, 서비스 포트 격리, 트래픽 제한, 남은 의존성 경고를 다시 검토한다.
3. 모의투자 계좌/주문 갱신에 여러 저장 호출을 쓰는 기존 코드가 있다. 같은 계정의 동시 주문과 장애 중간의 일관성은 DB 트랜잭션/동시성 테스트가 필요한 후속 과제다. 금융 로직을 전시 직전에 대폭 바꾸지는 않았다.
4. 기본 요청 제한은 한 IP 기준이다. 전시 회원가입은 시간당 120회, 실패 로그인 15분당 30회다. 많은 기기를 프록시 하나로 연결하면 운영 조건에 맞는 조정이 필요하다.
5. 원래 라우팅되지 않는 AgentSimulator/PrototypeDashboard의 localhost 하드코딩과 이전 UI/타입 문제가 남아 있다. 실제 /simulator는 MarketSimulatorPanel을 사용한다. 폐기 예정 파일은 자동 삭제하지 않았다.
6. 기존 DB의 password 고유 인덱스가 있다면 스키마 변경만으로 제거되지 않는다. bcrypt 솔트 때문에 보통 충돌하지 않지만 인덱스 정리는 운영자가 백업 후 별도 검토한다.
